## Regulatory Guidelines and legal requirements

Check the dataset's license. Write down the name of the license and explain what it allows you to do with the data. For example, check whether you are allowed to download, copy, edit, share or use the data for commercial purposes.

Check whether attribution is required. Some licenses require you to name the original creator or source. Explain whether you must credit the author when using the dataset.

Check for copyright restrictions. Explain whether the dataset is protected by copyright and whether permission is needed before it can be used or changed.

Check for personal data. Look for fields that could identify a person, such as:

name

username

email address

telephone number

home address

IP address

exact location

account ID

photographs

Consider indirect identification. A dataset may not include a person's name, but several fields could be combined to identify them. For example, age, location, job title and an account number might reveal someone's identity.

Explain how UK GDPR may apply. If personal data is included, explain that it must be collected, stored and used fairly, lawfully and only for a clear purpose.

Explain how the Data Protection Act 2018 may apply. State whether personal information is being handled safely and whether any unnecessary personal fields should be removed.

Check whether sensitive information is included. Look for information about health, ethnicity, religion, political views or other sensitive areas. Explain that this type of information needs stronger protection.

Check whether the dataset has been anonymised. Explain whether personal details have been removed or replaced with codes. Also consider whether the codes could still be linked back to individuals.

Consider data minimisation. Explain whether every field is needed for the analysis. Personal or irrelevant fields should not be kept simply because they are available.

Check the website's terms and conditions. The website hosting the dataset may have rules about downloading, scraping, sharing or commercially using its data.

Check the original platform's terms of service. If the information was collected from another website, app or social media platform, explain whether the collection method followed that platform's rules.

Check whether the dataset is free for all uses. Some datasets are free for education or research but require permission or payment for business use.

Consider how the data will be stored. Explain that data should be stored securely, with access limited to people who need it.

Consider how long the data should be kept. Personal data should not be stored for longer than necessary. Explain whether a retention period may be needed.

Explain what actions are required. Clearly state whether the organisation should remove fields, anonymise information, request permission, credit the author or obtain a suitable licence before using the dataset.

Check the number of records. Explain whether there are enough records to identify useful patterns and trends.

Check the number of columns. Explain whether the dataset contains enough useful fields without including too much unnecessary information.

Check whether the required fields are present. Link this to the client's requirements.

Check for missing values. Identify fields containing blanks, null values, "N/A", question marks or other missing-value markers. Explain how these could reduce accuracy.

Check for duplicate records. Explain whether the same record appears more than once and how duplicates could lead to incorrect totals.

Check for irrelevant fields. Identify columns that do not help answer the client's questions. Explain that these fields could make the dataset harder to understand.

Check the data types. Make sure dates are stored as dates, times as times, numbers as numbers and categories as text.

Check date and time formats. Explain whether the date and time values use one consistent format or several different formats.

Check category values. Look for different spellings, capitalisation or abbreviations for the same value, such as "YouTube", "Youtube" and "YT".

Check numerical values. Look for negative numbers where they are not expected, decimal values where whole numbers are required, or numbers stored as text.

Check for unusual values or outliers. Identify values that are much higher or lower than the rest. Explain that they may be genuine, but they should still be checked.

Check whether field names are clear. Explain whether the column headings are meaningful or whether they need to be renamed.

Check whether column descriptions are provided. Clear descriptions help analysts understand what each field means and reduce the risk of misinterpretation.

Check whether the data uses consistent units. For example, confirm that all durations use seconds or all currency values use the same currency.

Check whether any coded values are explained. If the dataset uses values such as 1, 2 and 3, explain whether a data dictionary shows what each code means.

Check whether the data can be sorted and filtered. Explain whether the structure makes it easy to find records and compare categories.

## Further Preparation Techniques

**Cleaning the data**

- **Remove duplicate records** so that the same information is not counted more than once.
- **Remove completely blank records** because they do not provide useful evidence for the analysis.
- **Deal with missing values.** Depending on the field, missing values could be:
  - removed
  - replaced with a suitable value
  - marked as "Unknown"
  - left blank but clearly documented
- **Remove irrelevant columns** to make the dataset easier to understand and process.
- **Correct spelling mistakes** so that the same category is not treated as several different categories.
- **Remove extra spaces** from the beginning or end of text values.
- **Check and correct unusual values.** Outliers should not automatically be deleted. First check whether they are genuine values or data-entry errors.

**Standardising the data**

- **Standardise capitalisation.** For example, change "video", "Video" and "VIDEO" to one agreed value.
- **Standardise category names.** For example, replace different abbreviations with one consistent platform or content-type name.
- **Standardise date formats.** Make sure all dates use the same format, such as DD/MM/YYYY.
- **Standardise time formats.** Convert time values to one format, such as HH:MM using the 24-hour clock.
- **Standardise numerical fields.** Remove symbols or text that stop numerical values from being used in calculations.
- **Standardise measurements and units.** Convert values so that they all use the same unit.
- **Decode coded information.** Replace unexplained numbers or letters with clear category names, or provide a lookup table.

**Restructuring the data**

- **Split combined fields.** For example, separate a date-and-time field into one date column and one time column.
- **Split dates into useful parts.** New fields could include:
  - day
  - day of the week
  - week
  - month
  - quarter
  - year
- **Group time values into periods.** For example:
  - morning
  - afternoon
  - evening
  - night
- **Combine fields where appropriate.** Only combine fields when this will make the analysis clearer.
- **Rename unclear field headings** so that users can easily understand what each column contains.
- **Use consistent naming conventions.** For example, use post_date, content_type and engagement_count rather than mixing several naming styles.

**Protecting the data**

- **Remove personal information** that is not required for the analysis.
- **Anonymise identifying fields** by replacing personal details with non-identifying codes.
- **Group detailed values into wider categories** when exact information could identify someone. For example, use age ranges instead of exact ages where appropriate.

**Improving the analysis**

- **Create calculated fields.** Depending on the dataset, these could include:
  - engagement rate
  - total interactions
  - percentage change
  - average value
  - age group
  - time-of-day group
  - performance category
- **Balance categories where necessary.** If one category has many more records than another, consider sampling or using percentages to make comparisons fairer.
- **Standardise measures before comparing groups.** Raw totals might not be fair when groups have different sizes. Rates, averages or percentages may provide a better comparison.
- **Filter the data to the required time period.** Remove records that fall outside the dates relevant to the client.
- **Add another verified dataset if important information is missing.** Before combining datasets, check that the field names, categories, dates and units are compatible.

**Checking the prepared data**

- **Apply validation rules** to prevent incorrect values from being entered.
- **Use presence checks** to identify required fields that are blank.
- **Use range checks** to identify numerical values outside sensible limits.
- **Use list checks** so that category fields only contain approved values.
- **Use format checks** for dates, times, IDs and other structured information.
- **Retest the dataset after cleaning** to make sure the changes have worked correctly.
- **Keep a record of every change made.** A cleaning log makes the process transparent and allows someone else to understand how the final dataset was produced.
